**Назначение:** перечень фактически существующих механик + планы из бэклога, их сильные/слабые стороны, связанность, обоснованность, целостность и соответствие концепту и исследованию сообщества.

## 0. Источники и оговорки

**Якорь концепта:** `Documentation/Design/Mirenhold_Vision_v0.1.md` v0.2.
Принципы: (1) свобода времени, (2) несколько способов играть, (3) добровольное сотрудничество, (4) любопытство и атмосфера, (5) значимый прогресс, (6) понятный риск, (7) целостность. Шесть циклов: бой, исследование, добыча, ремесло, общественные дела, торговля. Первый законченный цикл = Этап 1 Foundation (две standalone-сессии) + Этап 2 Connected Region (связывание обменом и поселением) — см. маппинг Vision §7 и Roadmap. Вне этапов: осады, открытый PK, политика узлов, дома, фермерство, питомцы, десятки профессий, большая рейдовая лестница.

**Исследование:** `Research/Mirenhold_MMO_Community_2025-2026.md` (каноническая копия в репо; provenance в файле; срез 01.2025–09.2026, 24 ветки, качественная выборка, не рынок). Частоты — число веток с темой, не доля аудитории: T свобода времени 17, W исследование/атмосфера 17, S общение/кооперация 16, Q качество боя/управления/UI 15, P ценность прогресса 12, M монетизация 11, I классы/билды 10, E экономика/крафт 9, D опасность/PvP 8, R доверие 4, B боты/читы 3. Шесть противоречий: соло↔социо, вертикаль↔долговечность, маркеры↔открытия, full loot↔потеря часов, статус↔трансмаг, живые события↔FOMO. Три механизма FOMO: исчезновение доступа, давление эффективности, социальное отставание. Главная гипотеза исследования для Mirenhold: атмосферное приключение + накопительный прогресс + естественное сотрудничество + свой темп.

**Проверенный код (факт):**

## 1. Боевое ядро

### 1.1 Бой real-time с выбором цели (таргет-лок, автоатака)
- **Status:** Approved
- **Пять вопросов:** зачем — преодоление и свой стиль; решение — дистанция/защита/момен��; как — `playerAttack` → `combatInitiation` → `combatResult`, сервер-авторитет; связи — подготовка, лут, кооперация; проверка — игрок объясняет различия воин/маг и добровольно повторяет бой.
- **Сильные:** сервер-авторитет + лаг-компенсация (`00`: timestamps/requestId), отложенный урон по нотифаеру/попаданию проджектайла (честность анимации), базовая читаемость (таргет-фрейм, кастбар, красная рамка low-HP, floating numbers).
- **Слабые:** Q-риски из исследования (15/24): выбор цели, задержки, обратная связь. В `TODO.md` закрыта пачка багов таргет-лока/синхронизации проджектайлов чужих игроков/моб-толкания/дергания — значит, зона хрупкая, регрессии вероятны. AoE — заготовка, DoT/HoT — нет (режет глубину билдов).
- **Связанность:** высокая — вход для Mastery, Fellowship, Pity, Bestiary, Item Soul, Reputation, Champions.
- **Целостность:** ядро цело, но без DoT/HoT и полноценного AoE тактика беднее заявленной.
- **Fit к видению:** прямое — «понятный риск», «классы различаются решениями». Условие: воин/маг должны отличаться не анимацией, а решениями (дистанция/каст/контроль/цена ошибки).
- **Fit к исследованию:** Q15 — первое, что проверяют; провал боя обесценивает всё остальное. S-правила наград тоже завязаны на читаемость вклада.
- **Вердикт:** `Оставить + Доработать`. Следующее: плейлист-проверка «выбор цели → попадание → опасная атака → подбор» (S12/S20 в исследовании), затем решение по DoT/HoT/AoE, а не наоборот.

### 1.2 Классы и скиллы (воин/маг, каст, проджектайлы, баффы/хилы)
- **Status:** Approved
- **Сильные:** SP + золото + книга как тройная цена обучения (см. 3.1) даёт выбор; скиллбар персистится (`skillBarState/slotUpdated`); кулдауны переживают релог.
- **Слабые:** I10 из исследования требует узнаваемых ролей и отличий в ощущениях; при бедных эффектах (нет DoT/HoT) воин/маг рискуют стать «цветом урона». Поддержка/контроль (обещаны видением после проверки) пока тонкие.
- **Связи:** SkillShop (NPC-тренеры), Mastery (пассивки), stats (атрибуты → каст/урон), VFX/SFX.
- **Вердикт:** `Оставить`. Проверка из видения: игрок словами объясняет разницу воин/маг. Расширять поддержку только после неё.

### 1.3 Мобы, AI, спавн, движение
- **Status:** Approved
- **Сильные:** динамическая навигация (small/big агенты по `AGENTS.md`), сервер-авторитет движения, точки возврата в зону.
- **Слабые:** исторически самая багогенная зона; любое изменение скорости (Zone Events!) — регресс-риск. Поведение «не атаковать, если нет места» — правильное, но надо наблюдать, не стали ли мобы пассивными.
- **Связи:** Champions, Zone Events (множитель скорости), Reputation (`faction_slug`), Bestiary, Pity.
- **Вердикт:** `Оставить + заморозить трогания без регресс-сценариев`.

## 2. Прогрессия (накопительная, без FOMO — ядро ставки)

### 2.1 Опыт, уровни, статы, OOC-реген
- **Status:** Approved
- **Сильные:** простое понятное ядро; `reason` (`mob_kill/quest_complete/zone_explored`) позволяет разделять боевую/мирную прокачку — этого требует видение («боевой уровень не универсальный пропуск»).
- **Слабые:** темп развития и границы боевой/мирной прогрессии — открытые решения видения (п. 8.2). Без таблицы баланса числа висят.
- **Fit:** P12 (умеренный вертикальный рост без обнуления), T17 (нет серий входов — долг см. 2.2 не отнимает доступ).
- **Вердикт:** `Оставить`. До баланса зафиксировать таблицу XP-кривой отдельно (по `Design/README.md` числа живут в таблице баланса, не в тексте).

### 2.2 Цена смерти: XP Debt + Resurrection Sickness + респавн-зоны
- **Status:** Approved
- **Сильные:** долг вместо потери часов — точно в точку противоречия D (риск без уничтожения удовольствия) и T (перерыв не карается). Понятный риск по видению.
- **Слабые:** числа (долг %, длительность sickness) — открыты; HUD-баг с «текущее > максимального» был закрыт — следить. Телепорт-UX («летит камера») в TODO `[ ]` — проверить, не ломает ли ощущение риска/возврата.
- **Вердикт:** `Оставить`. Не превращать в full loot без отдельного решения аудитории (исследование прямо запрещает выводить это из любви к опасности).

### 2.3 Skill Mastery (use-based, 0–100, soft cap)
- **Status:** Approved
- **Сильные:** независим от уровня — свой путь воина/ремесленника боя; защита от фарма слабых; milestone-пассивки без новой системы (переиспользование `ActiveEffectStruct` — пример целостности).
- **Слабые:** `crit_chance/parry_chance` — новые атрибуты, нужен сквозной учёт в `CombatCalculator` и UI; иначе тиры «невидимые». Клиент только читает — где игрок видит прогресс (статы vs отдельная вкладка) решено, но проверить читаемость.
- **Fit:** P (долгая цель без обнуления), I (стиль боя), видение «ремесло развивается практикой» — та же философия.
- **Вердикт:** `Оставить + Доработать видимость` (прогресс-бар, момент tier-up через `mastery_tier_up` уже есть — проверить звук/иконку).

### 2.4 Репутация и фракции
- **Status:** Approved
- **Сильные:** мир реагирует — лучшая опора для «отношений и поселений»; связывает бой, квесты и торговлю одним числом с понятными порогами.
- **Слабые:** full aggro стражи при <−500 — только MVP (блок диалога), не атака; ок. Экономика скидки маленькая — и это правильно (не ломает цены), но игрок должен её замечать.
- **Вердикт:** `Оставить`. Это мост к общественным делам — не разбирать.

### 2.5 Титулы (+ локализация, неймплейт)
- **Status:** Approved
- **Сильные:** дешёвый долговечный прогресс (P) и статус без силы (компромисс противоречия «статус vs трансмог»): узнаваемый заработанный сет/титул.
- **Слабые:** бонусы за титулы — проверить, не создают ли обязательную гонку за титулом под группу (давление эффективности, механизм FOMO №2).
- **Вердикт:** `Оставить`, бонусы держать косметико-минимальными до теста.

### 2.6 Исследование зон + worldNotification
- **Status:** Approved
- **Сильные:** anti-stagnation hook за копейки; флаг как ключ к диалогам (`explored_X → ветка NPC`) — связка исследование→история из коробки.
- **Слабые:** требует геометрии зон (`min/max_x/y`) и контента; без миникарты/карты (см. §6) игрок может не найти зоны вовсе. `zones` vs `spawn_zones` vs `respawn_zones` — три сущности, легко перепутать в дизайне.
- **Fit:** W17 (ориентиры, скрытые маршруты), T (постоянная цель, не исчезает).
- **Вердикт:** `Оставить`. Следующее — дизайн первого региона (схема мест по `Design/README.md`), а не новые типы уведомлений.

## 3. Предметы и экономика нужды

### 3.1 Инвентарь, экипировка, вес, слоты, ограничения
- **Status:** Approved
- **Сильные:** полный базовый цикл «нашёл → надел → видно другим» (баги видимости экипировки других закрыты). `apply_on: equip/use` — чистый принцип бонусов.
- **Слабые:** класс-лок предметов (может ли маг надеть латы) — проверить enforcement: в плане он числился отсутствующим; если так и осталось — дыра в I (ролевая читаемость). Двуручность — проверить.
- **Вердикт:** `Оставить + проверить два enforcement` (класс, двуруч) одним тестом.

### 3.2 Прочность, износ, ремонт (двухзонная модель)
- **Status:** Approved
- **Сильные:** создаёт спрос и выбор подготовки (маршрут ↔ ремонт) + sink против инфляции — то, чего требует E.
- **Слабые:** главный риск из видения и исследования: «износ становится налогом», «обслуживание прерывает сессию». Прямая цитата исследования: проверить, создаёт ли ремонт решения о подготовке или регулярно прерывает интересную сессию. Баланс частоты/цены — открыт.
- **Вердикт:** `Доработать осторожно`: сначала телеметрия «сколько % сессии уходит на обслуживание», затем ослаблять, а не усиливать. Без уничтожения любимой вещи (принято видением).

### 3.3 Лут, харвест трупов, Pity, Item Soul
- **Status:** Approved
- **Сильные:** эталонная связка «память предмета» (P12: игрок помнит находку и объясняет зачем она) + защита от невезения (удовлетворённость) + харвест как тактильный финал боя. Pity скрыт, hint — нарративом: верно по дизайну.
- **Слабые:** tier-бонусы Item Soul и Pity-модификатор надо видеть в `stats_update`/`effective` — иначе «невидимая щедрость». Харвест-VFX собираемых трупов отсутствует (только UI) — слабая аффорданс-точка (TODO-UX про «надпись рядом с трупом» закрыт частично — проверить).
- **Вердикт:** `Оставить`. Это сердце «ценного лута» — не трогать числа до плейтеста, добавить только читаемость.

### 3.4 Вендоры, P2P-трейд, золото
- **Status:** Approved
- **Сильные:** минимальный жизнеспособный рынок: добыча из разных мест → повод двигаться и общаться (E9).
- **Слабые:** до открытой экономики нужны серверные проверки, атомарный обмен, история операций, жалобы/расследование (исследование, B3: низкая частота ≠ низкая цена). Аукциона нет — и не надо на Этапе 1.
- **Вердикт:** `Оставить + проверить два пункта`: tradable золота и атомарность P2P. Рынок/аукцион — `Отложить`.

### 3.5 Локализация предметов (`name_key`)
- **Status:** Approved
- **Вердикт:** `Оставить`. Технический гигиенический слой, на игру не влияет напрямую, но разблокирует RU/EN.

## 4. Мир как экосистема (главная ставка связности)

### 4.1 Чемпионы: Threshold / Survival / Timed (+ Rare-заготовка)
- **Status:** Approved
- **Сильные:** три разных ритма (фарм-триггер, «тот самый волк живёт 3 дня», планируемое событие) — retention без дейликов; server-wide счётчик = социальное событие без группы. Пример связки из дока (волки → Альфа → Клык → Охотник) — лучший кандидат на первый «вау-цикл».
- **Слабые:** баланс порогов (`champion_threshold_kills` default 100) и окон — нет; визуал эволюции (имя меняется, нужен переспавн/апдейт-пакет) — MVP через уведомление, ок, но проверить. Rare-логика (тикер) — отсутствует в коде; условие `on_kill` уже в данных, DayNight не нужен (см. §10).
- **Fit:** D (опасность с понятными правилами), S (повод собраться), P (гарантированный необычный + шанс редкого).
- **Вердикт:** `Оставить`. Rare — `Доработать условие` (не ждать сутки ради суток).

### 4.2 Zone Events (ambient-модификаторы + нашествия + обоз)
- **Status:** Approved
- **Сильные:** архитектурно зрело (snapshot, точки внедрения в Loot/Movement/Spawn); даёт «живой мир» без FOMO-насилия (повторяемые события, награды доступны позже — как требует исследование).
- **Слабые:** легко перегрузить (скорость мобов × событие × чемпион = хаос); клиентский UI расписания (`worldEventsSchedule`) — проверить наличие; иначе Timed-события «для своих».
- **Вердикт:** `Оставить, дозировать`: на Этап 1 — одно-два события («Волчий час», одно нашествие), не четыре сразу.

### 4.3 Бестиарий с постепенным раскрытием
- **Status:** Approved
- **Сильные:** знание меняет маршрут/тактику — проверка видения; анти-гринд скуки; связка с Pity (знаешь за чем охотишься) и Item→NPC.
- **Слабые:** без контента (записки/ранги) это «счётчик убийств»; Scholar-альтернатива pure-grind критична для мирных/соло.
- **Вердикт:** `Оставить + наполнить минимум`: 2–3 записки и один Scholar на Этап 1.

### 4.4 NPC, диалоги-графы, квесты, Item→NPC
- **Status:** Approved
- **Сильные:** самая связанная система: флаги, репутация, мастерство, предметы, исследование — всё входит в условия/действия (`change_reputation`, `learn_skill`, `open_vendor_shop`). Короткие ситуации с уликами и вариантами — ровно формат видения. WIO + Ambient = дешёвая атмосфера (W17).
- **Слабые:** глубина зависит от контента, а не кода; `evaluateInventory` — проверить; награды с превью предметов — есть, но тултипы вендора (ошибки «нет золота/места») — в TODO `[ ]`,UX-дыра.
- **Вердикт:** `Оставить`. Контент-приоритет Этапа 1: мирная история (пример — TBD; мельницу убрали из проекта: пример не должен диктовать архитектуру) на WIO + Item→NPC.

### 4.5 Социал: чат, эмоции, Fellowship (без группы)
- **Status:** Approved
- **Сильные:** Fellowship — точное попадание в S16: «вместе выгоднее» без принуждения, расписания и борьбы за добивание. Узнаваемые имена в хабе + чат + помощь в поле = социальность из исследования.

## 8. Связность: что держится, что висит

**Сильное ядро (проверено кодом):** бой → (Mastery, Fellowship, Reputation, Bestiary, Pity) → Threshold → чемпион → редкий дроп → Item Soul → Item→NPC → квест → вендор/репутация-скидка; исследование → флаг → XP + диалог; Zone Events × (лут/скорость/спавн) поверх всего; `worldNotification` как единая шина событий. Это не набор фич, а слои — лучшая часть проекта.

**Висячие концы (по приоритету починки):**
1. Мирный путь обрублен: добыча → крафт → заказ → поселение отсутствуют (6.1–6.3). Боевой путь богат, мирный — только исследование+харвест. Обязательство видения «две сессии» не выполняется.
2. Группа отсутствует при элите/чемпионах (4.5). Fellowship без группы — хорошо для поля, плохо для планирования.
3. Rare-тикер отсутствует в коде; условие `on_kill` уже в данных, DayNight не нужен (см. §10).
4. Item→NPC условие по предмету — подтвердить заполнение контекста (иначе диалоги для всех).
5. DoT/HoT и AoE — либо доделать минимум, либо убрать из протокола/дokов, чтобы не врать.
6. Карта/миникарта отсутствует при ставке на исследование (6.4).
7. Вендор-ошибки/тултипы и панель расходников — мелкие UX-дыры с большим Q-эффектом (6.11).
8. Миграции как файлы не сверяем — наблюдаемое состояние данных смотрим в свежем дампе БД (см. §10).

**Сделать минимально для Этапа 1 — Foundation (порядок):** 1) одна добыча + одно ремесло с выбором (закрывает мирную сессию); 2) дизайн первого региона (схема мест, скрытое место, опасный участок, элита); 3) 1–2 сокровища/головоломки; 4) таблица баланса; 5) UX-готовность (мини-карта, feedback'и, без glitches). Связанный settlement project (постройка + повторяемое дело) — Этап 2 Connected Region (см. Roadmap; маппинг Vision §7).
**Заморозить/отложить:** дейлики/еженедельки (конфликт T); фермерство/дома/маунты/питомцы/десятки профессий/рейды/осады/PK/аукцион/гильдии/погода (всё — вне Этапа 1 по видению).
**Решить до систем (видение п. 8):** правила участия/добычи; цена смерти/износ/темп; первая постройка/вклад/антиабуз; специализации ремесла/NPC-резерв/источники валюты; границы изменения мира; ПК/плотность/модель оплаты (предложение «не продавать силу» — зафиксировать).

**Проверка на плейтете (из исследования, нейтральные вопросы):** бой приятен сам по себе (повтор без цели)? Лут значим (помнят находку)? Мир тянет сойти с маршрута? Социальность возникает без просьбы? Свой темп (короткая vs длинная, возврат после перерыва)? Желание вернуться (фактический вход + «что дальше»)? Плюс чек видения: мирная сессия без убийств завершается полезным результатом; новичок находит дело в развитом поселении; прогресс пережил сбой.
