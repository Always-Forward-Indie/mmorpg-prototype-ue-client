## TL;DR

Этапы идут от проверки концепции к росту: сначала доказываем две сессии на одном регионе, потом связываем, потом тестируем вовне, потом расширяем. Переход — только по критериям, не по датам.

## Этапы

### Этап 0. Гигиена (текущий)

Доки приведены к дампу, структура задана, мусор описан миграциями 082/083 (не применены).
**Критерий перехода:** аудит без строк «док врёт», структура из README соблюдается.

### Этап 1. Вертикальный срез (Foundation)

Одна боевая и одна мирная сессия в долине Эмберфорда, каждая работает standalone (см. `Stage_1_Vertical_Slice.md`).
**Критерий перехода:** критерии успеха слайса выполнены на внутреннем тесте (см. плейт-тест-план).

### Этап 2. Связанный регион (Connected Region)

Пути, проверенные по отдельности на Этапе 1, пересекаются через обмен и проект поселения; мирный путь не требует охоты.
**Критерий перехода:** заказы между игроками идут без участия тестировщика; вклад не поглощает все находки.

### Этап 3. Внешний тест

Соло, вдвоём, малой группой; первая и повторная сессии; бойцы и мирные отдельно.
**Критерий перехода:** препятствия исправлены, возвраты без временных наград наблюдаются.

### Этап 4. Расширение

Второе поселение и углубление подтверждённых занятий.
**Критерий перехода:** добровольные возвращения, полезные обмены, ресурсы команды позволяют.

### Позже (вне scope)

Дополнительные профессии, социальные системы, сложный PvE, затем отдельная проверка PvP. Новое — только если сохраняет принципы и старые достижения.

## Правила

- Этап не начинается, пока не закрыт критерий предыдущего.
- Даты не назначаются до сверки объёма с командой.
- Наличие механики в коде ≠ готовность этапа (проверяется поведением).
